## 3. 技術方針（既定の選択）

### 3-1. 2Dの舞台（`app/stage/flat.js`）
- 量の部品は**SVGの2D**で描く（D20）。理由は3つある。実寸のものさしは透視投影の3Dでは作れないこと。見本 v1 が2Dであること。iPad で軽いこと。
- `#stage`（canvas）の上、`#caption`・`#toast`・`#counter` の下に `<svg id="flat">` を1枚置く。上の帯と下の棚のあいだ（`S.view.top - 54` から `S.view.H - S.view.bottom + 8`）に収める。単位は CSS ピクセル。
- API（部品から使う）：
  - `openFlat({ mat: false })`：`{ svg, W, H, top, bottom, ptr(e), layer(name), onResize(fn), close() }` を返す。開いている間は3Dのマットを隠し（`showMat(false)`）、`S.onTap = null`、`S.allowRotate = false`。
  - `clearStage()`（app.js）で必ず閉じる。部品の `dispose` からも閉じてよい（2回閉じても壊れない）。
  - アニメは `stage.js` の `tween` と `wait` を使う（`S.token` による打ち切りと「動きの量」の設定がそのまま効く）。毎フレームの物理（はかりの針・水面のゆれ）は `onFrame` を使い、`dispose` で外す。
- SVG の色は `tok()` で実際の値にしてから属性に入れる（落とし穴 §6）。字体は CSS の `--font-display`・`--font-ui`。
- 縦長・横長は部品ごとに配置を切りかえる（見本 v1 の各場面の `layout` と同じ考え方）。

### 3-2. 部品の作り
- 量の部品も `app/parts/<名前>.js` に置き、`mount(ctx)` で棚（`ctx.panel`）と2Dの舞台に出す。戻り値は `{ dispose, onResize, test }`。図形側の部品と同じ約束。
- 部品名は設計書 §1 の表のとおり（`kurabe`・`utsusu`・`ikutsubun`・`monosashi`・`karada`・`masu`・`hakari`・`tokei`・`jikan-obi`・`byou`・`masume`・`bundoki`・`tani-zoom`・`mitoshi`・`chizu`・`kakekko`・`korogasu`）。問題用の部品は `<名前>-quiz`（例：`tokei-quiz`）にしてよい。
- 共通の小道具は `app/parts/_flat.js`（SVGの生成、点の座標、はなまる、矢印、拡大鏡、字幕の出し方）。
- 見本 v1 の動きを移す：`reference/hakaru-mock-src/` の各場面（20-clock・30-water・40-scale・50-ruler・60-area・70-units）を部品と単元データに分ける。動きの水準は見本と同じかそれ以上にする。見本の「みる」は単元の `miru` タブ、「さわる」は `sawaru`、「ためす」は `tamesu` へ。
- 図形側の部品で代わりがきくものは新設しない。新設したときは理由を台帳に1行書く（例：E5 の円を転がす動きは2Dなので、3Dの `cylinder-roll` ではなく `korogasu` を作る）。
- テスト用ののぞき口 `test.auto()` を全部品に持たせる（巡回 E2E が1手ずつ進められるように）。2Dの舞台の上を実際にタップ・ドラッグさせる（`{ tap: {x,y} }`、`{ drag: ... }` を返す。必要なら `crawl.mjs` に2D用のドラッグを足す）。

### 3-3. 単元データ
- 形式は図形側と同じ（`tabs`・`zukan`・`mission`・`review`・`insights`・`praises`・`map`・`labels`・`demo`）。ファイルは `app/units/<id>.json`。
- `index.json` の各単元に `areas`（入口の id の配列）と `owner`（`katachi`／`hakaru`）を足す。図形側：r1・r2・r4・r5a・rj は `["katachi"]`、r5b・r6 は `["katachi","kasa"]`。量の単元は設計書 §0-1 の表の「入口」。A4 は `["katachi"]` で `owner: "hakaru"`。
- `app/units/areas.json`：`[{ id, name, icon, color }]` を6つ。並びは かたち・ながさ・かさ・たいせき・おもさ・じかん・ひろさ。色は `tokens.css` の変数名で書く。
- 文面はすべて下書き（`reviewed: false`）。子ども向けはひらがなの分かち書きにし、教科書の用語は漢字＋ルビ。保護者向けは漢字かな交じり。

### 3-4. 内容の量（網羅の下限。D9・D15）
- 本編の単元（12）：みる1以上（字幕と読み上げつきで最後まで流れる）、さわる2以上、ためす2種類以上（各3段の難しさ、1回5問以上。数は生成してよい）、つくる1以上、ずかん1以上（計算で出せるものはすべて）、思い出し問題10以上、つまずきの見立て（設計書の型をすべて）、ほめどころ2以上、学校の学習との対応（その単元の指導要領の項目をすべて）。
- ちょっと先（7）：みる1・さわる1・ためす1（3段）以上、思い出し問題6以上、見立て2以上。
- 問題の誤答の選択肢には、設計書の「つまずきの型」に当たるものを必ず混ぜる（例：時計の 7時55分 → 8時55分、ものさしの端が1 → 1cm多い答え、背の高い入れ物、目もりの数え違い）。
- 「ためす」の答え合わせは、正解でも不正解でも動きで確かめる（注いで比べる、針を動かす、0に合わせる、マスを数える）。1回目の不正解はヒントを1段進めてやり直し、2回目で動きで確かめて次へ（見本 v1 と同じ）。

### 3-5. 共通の仕組みに足すもの
- **実寸合わせ** `app/core/calibrate.js`：1円玉（直径は `benchmarks.json`）またはカード（85.60mm）を画面に当て、スライダーと±ボタンで合わせる。値は「1mm あたりの CSS ピクセル」として端末ごとに保存する（きょうだいで共有。記録の書き出しには入れない）。`devicePixelRatio` か画面の大きさが変わったら、合わせ直しを一度だけ促す。設定に「がめんの ながさ あわせ」を足す。合わせる画面は `index.html` に `calibSheet` を足して作る。
- **基準物** `data/benchmarks.json`：30件以上。形式 `{ id, name, len_mm?, vol_ml?, mass_g?, area_cm2?, approx, verified, src }`。設計書 §1-2 の物をすべて入れる。値は教科書・指導案にある「およそ」の値を使い、`src` に出典（URL か「教科書の例」）を書く。ランドセルは重さの基準に使わない。`precache.json` に入れる。
- **読みの道具** `app/core/yomi.js`：時刻（「7じ 55ふん」と読み上げ用の「7時55分」）、分の「ふん／ぷん」、杯の「はい／ぱい／ばい」、本・枚・個・回の読み、単位の読み上げ（g→グラム、kg→キログラム、mL→ミリリットル、dL→デシリットル、cm²→平方センチメートル など）。単体テストで読みを確かめる。
- **見当の記録**：見当を入れる問題（`mitoshi`）は、記録の種類を `<単元>.estimate`、`detail` を `{ q, guess, actual, unit, qty }` にする（qty は length／volume／mass／time／area）。`rules.js` に条件 `estErr`（`where` に合う記録の相対誤差の平均と件数を返す）を足し、単体テストを書く。
- **保護者画面「見当の力」**：量ごと（長さ・かさ・重さ・時間・広さ）に、最近の見当のずれ（％）を小さな折れ線で出す。件数が3未満の量は「まだ記録が少ない」と出す。見本の記録（demo）でも表示されるようにする。
- **ずかんの図**：`zukan.js` の `list` に、項目ごとの図（`fig`）を出せるようにする。`figs.js` に量の図を足す：`clock:H:M`、`masu:dL`、`scale:g:cap`、`ruler:mm`、`cells:[...]`（既存）、`rect:w:h`、`route:...`。思い出し問題の `fig` でも使う。
- **地図（ホーム）**：1段目に入口6つ（絵・名前・単元の数・うごく単元の数）、2段目に入口の中の単元を学年の帯ごとに並べる（今の帯と同じ「いまの がくねん」「ちょっと さき」）。進み具合・ずかんの数・じゅんび中・おうちのひとが ひらけます の表示は今と同じ。ミッションと保護者のボタンは今と同じ位置。入口から戻るボタンを付ける。

### H2 じかん（T1・T2・T3）

- T1 つくる「わたしの いちにち」：場面の絵カード8枚以上（おきる・あさごはん・がっこうへ・おひる・おやつ・ゆうごはん・おふろ・ねる）を、子どもが時計で時刻を合わせて帯に並べる。
- T3 つくる「えんそくの けいかく」：出発・到着・休けいを帯に置き、時間を求める（正時をまたぐ）。
- ずかん：T1「とけい ずかん」はちょうど12＋はん12＝24、「ふん ずかん」は 0〜59 の60（合わせた時刻を集める）。T3「1ぷん あて」の記録（ずれの秒数）。
- 問題の生成：やさしい＝ちょうど・はん、ふつう＝5分刻み（45・50・55分を4割以上）、チャレンジ＝1分刻み（56〜59分と12時台を混ぜる）。読む問題と合わせる問題を半々にする（合わせるほうが難しいため、合わせるを多めにしてよい）。
- テスト：全時刻（720）の読みが正しい（ふん／ぷん）、生成した問題に正解がちょうど1つ、誤答に T1・T2・T3 の型が入る。

### H3 ながさ（N1・N2・N2m・N3・U3）
- 部品：`kurabe`（端をそろえる・まっすぐにのばす）、`utsusu`（テープに写す）、`ikutsubun`（任意単位。すき間・重なり・大きさ違いを見せる）、`monosashi`（実寸。0に合わせる・1cm→10mmの拡大・1mものさし・まきじゃく）、`karada`（指2本の実測。指が置けない端末は2つの印を動かす）、`chizu`（道のりときょり）、`tani-zoom`（k・m のズーム）、`mitoshi`。
- N2 の実寸：合わせていない端末では、ものさしに「じっすんでは ない」の札を出し、本物を測る活動とからだものさしは、合わせ方の案内から始める。
- N3 の地図：区間の長さ（m）を持つ道のグラフを1枚作る（家・学校・公園・駅・図書館など8地点以上）。「1km さんぽ」は、同じ区間を2回通らずにちょうど1000m になる道をすべてビルド時に数えて `data/hakaru/routes.json` に凍結し、図鑑の総数にする。
- N2m「1m をつくる」：基準物の長さの組み合わせで、ちょうど100cm になる組をすべて数えて凍結する（使う物は8種以内、同じ物は3つまで）。
- U3：長さ・かさ・重さの3つの棚で、k（1000倍）と m（1000分の1）を同じ動きで見せる（見本 v1 の 70-units）。単位の表に kL と mg を「しょうかい」として置く。
- テスト：道と組の数が凍結値と一致、ものさしの目もりの位置が実寸の計算と一致（1mm 単位）、からだものさしの長さの計算。

### H4 かさ・おもさ（K1・K2・O3）

## 6. 落とし穴（見本 v1 で実際に踏んだもの）

- **SVG の属性に CSS 変数を書くと色が付かない端末がある**。`tok()` で値にしてから入れる。
- **非表示の SVG で `getTotalLength()` を呼ぶと例外になる**。try/catch で既定値に落とす。
- **水を傾けると水面が水平でなくなる**。入れ物の内側の多角形を「重力の向きに垂直な半平面」で切り、面積が水の量になる位置を二分探索で求める（見本 30-water の `waterPoly`）。注ぐ角度も、水面が口の角に届く角度を二分探索で求める（`tiltFor`）。
- **入れ物を持ち上げて注ぐとき、注ぐ先の入れ物と重なる**。注ぐ先の左右どちらに余白があるかで、注ぐ口（右の角／左の角）を選ぶ。
- **時計の長針は、指の角度の差（±30分で折り返し）を足していく**。角度をそのまま時刻にすると、12をまたいだときに1時間ずれる。離したら1分に丸める。
- **はかりの針はばねの式で動かし、経過時間で進める**（フレーム数に依存させない）。振り切れたら止め金で跳ね返す。
- **からだものさしは、指ごとに pointerId を覚え、`touch-action: none` と pointer capture を付ける**。iOS は画面の端の指で `pointercancel` が来る。
- **実寸は CSS ピクセルと mm の比で決まる**。ブラウザの拡大・画面の回転で変わるので、変わったら合わせ直しを促す。
- **読み上げの文は画面の文と分ける**（「7じ 55ふん」→「7時55分」、「1dL」→「1デシリットル」）。端末の声は漢字のほうが正しく読む。
- 図形側の落とし穴（`docs/night-run-01.md` §5 と `HANDOFF.md` の生きている注意事項）も同じく守る。特に、描画ループの例外で全画面が固まる件と、棚の高さを測り直す件。
